# 식수체크 시스템 요구사항명세서 (PoC)

## 1. 프로젝트 개요
- **프로젝트명**: 사내 식수(점심/석식) 체크 시스템
- **배경**: 기존 사용 앱 "소담"이 본사와 타 업체 계약으로 인해 더 이상 사용 불가능해짐에 따라, Cursor AI를 활용해 자체 대체 시스템을 구축한다.
- **목표**: 직원이 휴대폰으로 간편하게 점심/석식 식사 여부를 신청하고, 담당자가 신청 현황을 실시간으로 확인·다운로드할 수 있는 시스템을 구축한다.
- **개발 도구**: Cursor AI + Python (Streamlit)

## 2. 적용 범위 (1차 PoC)
- 단일 사업장, 약 100명 이하 규모
- **포함**: 직원 신청(체크) 기능, 자동예약(반복신청) 기능, 관리자 대시보드
- **제외(2단계 이후로 연기)**: QR/바코드 스캔, 얼굴인식 카메라를 통한 실제 식수 인원 확인. 1차 PoC에서 실제 식사 인원 확인은 기존 방식(식당 입구에서 담당 직원이 종이에 수기 체크)을 그대로 유지한다.

## 3. 이해관계자 및 권한
| 구분 | 대상 | 권한 |
|---|---|---|
| 일반 직원 | 전 직원(사번 없음, 이름+부서로 식별) | 본인 신청 입력/수정(마감 전), 자동예약 설정 |
| 관리자 | 공무팀 담당자 여러 명 + 식당(급식) 담당자 | 전체 신청 현황 대시보드 조회, 엑셀 다운로드 |

- 부서별 별도 권한 분리는 필요 없음. 관리자 그룹은 전체 데이터를 동일하게 조회한다.

## 4. 기능 요구사항

### 4.1 직원용 – 식수 신청 (체크)
- 이름 + 부서 선택(또는 검색)으로 본인 식별 후 진입 (로그인 계정/비밀번호 불필요)
- 오늘 점심 "먹음/안 먹음", 오늘 석식 "먹음/안 먹음"을 각각 선택
- 각 항목은 마감시간 전까지 자유롭게 변경 가능
- **마감시간**: 점심 = 당일 오전 8시 40분, 석식 = 당일 오후 1시 40분(13:40)
- 마감시간이 지나면 해당 항목은 입력/수정 잠금(비활성화) 처리
- 마감시간까지 아무 것도 체크하지 않은 경우, 자동으로 "안 먹음"으로 간주하여 집계

### 4.2 직원용 – 자동예약(반복 신청) 설정
- 직원별로 요일 단위 기본 패턴을 설정할 수 있는 화면 제공
- 설정 항목: 요일(월~일) × 식사구분(점심/석식) 조합별 기본값("먹음"/"안 먹음")
  - 예: 월~금 점심은 "먹음", 수요일 석식만 "안 먹음" 등
- 매일 마감 전, 해당 요일의 자동예약 패턴이 그날의 기본 신청값으로 자동 반영됨
- 직원은 예외가 있는 날에 한해 마감 전까지 그날의 값만 직접 변경 가능 (변경 시 자동예약 기본 패턴 자체는 바뀌지 않고, 해당 날짜만 예외 처리됨)

### 4.3 관리자용 – 대시보드
- 오늘(또는 조회 날짜 기준) 점심/석식 각각 "신청 인원 수" 실시간 표시
- 날짜별/기간별 조회 및 추이 확인 가능
- 신청 내역 리스트(이름, 부서, 점심여부, 석식여부, 제출방식: 자동적용/수동변경) 조회
- 엑셀 다운로드 기능 (급식 준비/조리량 조절 등 내부 관리 목적)
- 신청→집계→대시보드 반영까지 전 과정 자동 처리 (관리자의 별도 검토·승인 단계 없음)

## 5. 비기능 요구사항
- **디바이스/네트워크**: 개인 휴대폰에서 외부 인터넷으로 자유롭게 접속 가능한 환경 기준으로 설계 (사내망 제한 없음)
- **접근 방식**: 고정 URL/QR코드 하나로 상시 접속 (직원용 별도 설치 앱 불필요)
- **데이터 용도**: 정산(비용 청구) 목적이 아닌, 조리량 조절 등 내부 인원 파악 목적. 따라서 회계/정산 수준의 데이터 정합성 검증 로직은 불필요
- **개인정보**: 이름, 부서 정도의 일반 업무 정보만 다루며, 민감 개인정보(얼굴 등)는 1차 PoC에 포함하지 않음

## 6. 데이터 구조 (제안)

### 6.1 직원 마스터
| 컬럼 | 설명 |
|---|---|
| 이름 | 직원 이름 |
| 부서 | 소속 부서 |

### 6.2 자동예약(반복 패턴) 테이블
| 컬럼 | 설명 |
|---|---|
| 이름 / 부서 | 직원 식별 |
| 요일 | 월~일 |
| 점심기본값 | 먹음/안먹음 |
| 석식기본값 | 먹음/안먹음 |

### 6.3 일별 신청(체크) 테이블
| 컬럼 | 설명 |
|---|---|
| 날짜 | YYYY-MM-DD |
| 이름 / 부서 | 직원 식별 |
| 점심여부 | 먹음/안먹음 |
| 석식여부 | 먹음/안먹음 |
| 반영방식 | 자동예약 적용 / 수동변경 / 미제출(자동 "안먹음") |
| 최종제출시각 | 타임스탬프 |

## 7. 비즈니스 규칙 요약
1. 점심 신청 마감: 당일 08:40 / 석식 신청 마감: 당일 13:40
2. 마감 후에는 해당 식사에 대한 값 변경 불가
3. 자동예약 패턴이 있는 직원은 매일 마감 전 해당 요일 기본값이 자동 반영되며, 예외 발생 시 당일 값만 직접 수정 가능
4. 마감까지 미제출(자동예약도 없는 경우) 인원은 자동으로 "안 먹음" 처리
5. 전체 프로세스(신청 → 집계 → 대시보드)는 사람의 개입 없이 자동 처리됨

## 8. 향후 확장 계획 (2단계 이후, 이번 PoC 범위 아님)
- QR/바코드 스캔 또는 얼굴인식 카메라를 통한 실제 식수 인원 자동 확인
- "신청 인원"과 "실제 식수 인원"의 차이를 관리자가 한눈에 비교할 수 있는 화면 추가
